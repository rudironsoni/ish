Non-negotiable project constraints

1. iox is a Linux-like virtual userspace subsystem for iOS.
2. The target is maximum practical Linux userland compatibility.
3. The target is not generic POSIX compatibility.
4. The target is not literal full Linux kernel compatibility.
5. Real host `fork()` is not the foundation.
6. Real host image replacement is not the foundation.
7. Arbitrary native binary loading is not the foundation.
8. WAMR is a secondary execution backend for WASM/WASI images only.
9. iox is the single owner of task, fd, vfs, signals, tty, `/proc`, `/dev`, clocks, env, and exec semantics.
10. WAMR must not create a separate process, filesystem, or signal universe.
11. There must be exactly one canonical execution object: `iox_task`.
12. `iox_context.c` must not survive as a competing process model.
13. Global FD ownership must not survive.
14. PTY, job control, sessions, process groups, signals, and `/dev/tty` are mandatory core requirements.
15. Build and test support must be iOS-only.
16. macOS-native execution is not acceptable as proof of correctness.
17. Tests are mandatory architecture, not follow-up work.
18. No feature is complete without automated evidence.
